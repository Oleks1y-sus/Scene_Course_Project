# QA та перевірка перед захистом

## 1. Автоматичні перевірки

```bash
npm run typecheck
npm run lint
npm run build

cd server
npm run typecheck
npm test
npm run build
```

Очікувано: 0 помилок TypeScript, усі Vitest-тести зелені, production build успішний.

> У середовищі з обмеженим sandbox `next build` може не мати дозволу на spawn worker-процесів. На звичайній машині / Vercel / Render ця проблема відсутня.

## 2. Smoke-сценарій вручну

1. **Реєстрація**: `/register` → нове ім’я, пошта, сильний пароль, згода → код → вхід.
2. **Профіль**: змінити ім’я/біо, обрати пресет-аватар, завантажити фото.
3. **Зміна пошти**: вказати нову пошту + пароль → код на нову адресу → підтвердити.
4. **Безпека**: змінити пароль → інші сесії завершено; вийти й увійти з новим паролем.
5. **Каталог**: пошук, категорії, статуси, сортування, пагінація; завершені/скасовані приховані за замовчуванням.
6. **Обране**: додати/прибрати; власний захід додати неможливо.
7. **Створення**: назва з `<script>` → 422; назва з лайкою → захід `PENDING`, у публічному каталозі не видно; власник бачить «На модерації».
8. **Реєстрація на захід**: зареєструватися, скасувати, перевірити лічильник; власний захід — заборонено.
9. **Ефір**: власник натискає «Розпочати» → `LIVE`; «Завершити» → `COMPLETED`, реєстрації стають `ATTENDED`.
10. **Скарга**: інший користувач скаржиться на захід; повторна скарга → 409.
11. **Адмін**: `/admin` під USER → редірект; під ADMIN → скарги, приховати/відновити, тіньовий бан, блокування, видалення.
12. **Новий адмін**: створити, отримати тимчасовий пароль, увійти, змінити пароль, отримати доступ.
13. **Видалення користувача**: видалити тестового користувача → його заходи зникають з каталогу.
14. **CSRF**: POST без `Origin` → 403; підроблений Origin → 403.
15. **IDOR**: відкрити чужий `/events/[id]/edit` → відмова; PATCH чужого заходу → 403.

## 3. W3C HTML Validator

1. Задеплойте проєкт.
2. Відкрийте <https://validator.w3.org/> → *Validate by URI*.
3. Перевірте `/`, `/login`, `/register`, `/events`, `/events/[id]`, `/create`, `/profile`, `/admin`.
4. Для приватних сторінок або використайте *Validate by File Upload* збереженої HTML-сторінки, або тимчасово зніміть захист у тестовому середовищі.
5. Виправте помилки, що стосуються реалізованого коду. Попередження від Next.js (наприклад, `nonce`) зафіксуйте у звіті.
6. Додайте скріншоти результату в звіт.

Типові артефакти Next.js: inline RSC-скрипти, `data-*` атрибути — не є помилками HTML.

## 4. W3C CSS Validator

1. <https://jigsaw.w3.org/css-validator/>.
2. Перевірте опубліковані CSS-файли (у production вони мініфіковані; для звіту можна завантажити `src/app/globals.css` окремо або використати URL зібраного CSS).
3. Сучасні властивості (`backdrop-filter`, `aspect-ratio`, `line-clamp`) можуть давати попередження — це припустимо; помилки синтаксису усуваються.
4. Додайте результат.

## 5. PageSpeed Insights

Перевірте:
- `/`
- `/events` (після входу; для Lighthouse використайте тестовий акаунт або публічну сторінку входу)
- `/login`

Команда:
```bash
npx lighthouse https://your-app.vercel.app --view
```

Або <https://pagespeed.web.dev/>. Зафіксуйте Performance/Accessibility/Best Practices/SEO та Core Web Vitals. Для покращення:
- переконайтеся, що Render не «спить» (Starter);
- залишайте зображення SVG/WebP;
- не додавайте важкі клієнтські бібліотеки.

## 6. Консоль браузера

Відкрийте DevTools → Console на кожній сторінці. Не має бути:
- `Uncaught` помилок;
- 404/500 на ресурсах;
- CSP-порушень (окрім свідомо дозволених inline-стилів Next.js).

Мережа: переконайтеся, що запити йдуть на `/api/v1/*` (same-origin), а не напряму до БД.

## 7. Адаптивність

Перевірте ширини: 320, 360, 390, 414, 768, 1024, 1280, 1440.
- Немає горизонтальної прокрутки.
- Меню-бургер відкривається/закривається, Escape закриває.
- Таблиці/ряди адмінки та профілю переносяться, кнопки не обрізаються.
- Модальні вікна не виходять за межі екрана.

## 8. Доступність

- Усі поля мають `label` і `aria-invalid`/`aria-describedby` при помилках.
- Фокус видимий (outline).
- Кнопки-іконки мають `aria-label`.
- Діалоги мають `aria-labelledby`; Escape/backdrop закривають.
- Контраст тексту на темному фоні — перевірте Lighthouse Accessibility.

## 9. Безпека (ручні атаки)

| Атака | Очікування |
| --- | --- |
| `<script>alert(1)</script>` у назві | 422, HTML заборонено |
| SQL `' OR 1=1 --` у пошуку | параметризований запит, без помилок/витоку |
| Підроблена cookie | 401, сесія не знайдена |
| POST без Origin | 403 CSRF |
| Чужий `PATCH /webinars/:id` | 403 |
| USER на `/api/v1/admin/stats` | 403 |
| 6+ невдалих паролів | блокування 15 хв |
| 6+ спроб OTP | `OTP_ATTEMPTS_EXCEEDED`, новий код |
| Завантаження `.svg`/`.exe` | 415 |
| Завантаження 3 МБ | 413 |
| Скарга на власний захід | 403 |
| Видалення останнього адміна | 409 |

## 10. Що додати у звіт

- Скріншоти головної, каталогу, деталей, створення, профілю, адмінпанелі.
- Скріншоти W3C HTML/CSS, PageSpeed, консолі.
- Таблицю покриття вимог (див. `docs/REQUIREMENTS-CHECKLIST.md`).
- Опис архітектури та захисту.
- Посилання на репозиторій, Vercel, Render.
